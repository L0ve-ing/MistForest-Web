**网页版范围与实施建议 · 2026-11-03**

2026-11-04 更新：本地联机首版已实现，当前功能和验证边界见《网页版使用说明.md》与根 README。下面保留前期方案作为背景；实际通信采用 HTTP 动作提交与 SSE 状态推送，避免为回合制房间引入额外 WebSocket 依赖。

已确认：第一版支持联机，同时适配电脑和手机。本轮只完成现有源码的精简和模块整理，未实施网页版。

现有源码和美术已经足够开始开发，无需重新提供。需要重做的是浏览器界面和通信接入，规则应继续使用同一套 C++ 裁判，避免两套规则长期分叉。

建议第一阶段结构：浏览器负责显示和输入，经 WebSocket 连接独立房间服务；服务端调用现有 C++ 规则，校验动作并按玩家身份生成受限视图。网页只接收该玩家可见的数据，隐藏坐标和完整裁判状态留在服务端。现有 `player_view`、动作校验和批量原子执行可作为复用起点，但还需要新接口及序列化适配。

现有 `Session` 是原生 TCP 会话，含建房、连接、同步和恢复；不能把目前的 Windows 程序直接当作网页交付。需要新增 WebSocket 接入、房间码、玩家席位令牌、心跳、重连和状态恢复。WebSocket 提供浏览器与服务端双向消息通道，见 [MDN WebSocket 文档](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API)。浏览器客户端与现有 EXE 是否跨端互通尚未确定；首版网页玩家之间联机与兼容原生客户端是两个不同工作项。

复用与改写边界：

| 部分 | 建议处理 |
| --- | --- |
| `game`、`rules`、`damage`、`ai` | 服务端复用；以受限视图和动作接口连接网页 |
| `editor/map_editor`、`action_selection`、`tutorial`、播放状态机 | 已有平台无关逻辑，按网页实际需求封装；客户端是否使用 WebAssembly 后续决定 |
| PNG 素材、地图数据 | 复用并整理为网页资源；增加预加载和缓存 |
| Win32 窗口、GDI/GDI+ 绘图、文件对话框 | 新建网页实现；地图导入导出改用浏览器文件交互 |
| 原生 `network` | 复用协议含义和恢复规则；新增网页通信及独立服务端生命周期 |

手机适配建议从布局和操作一起做：横屏优先，竖屏将操作区改为可展开底栏；棋盘尽量保留完整格子，战报和说明折叠显示。点选角色、点目标、确认执行应有明确反馈；全部必要功能能触摸完成，技能说明不能依赖鼠标悬停或键盘快捷键。可用统一 Pointer Events 接收鼠标、触摸和触笔输入，见 [MDN Pointer Events 文档](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)。

首个可验收闭环建议为：电脑与手机打开同一地址，创建/加入房间、选择角色、完成一局；手机切到后台后返回可重新同步；刷新或短暂断线后能恢复席位；不同玩家得到各自可见的信息。应在真实 Android 和 iPhone 上验收触摸、地址栏变化及后台恢复，不能只靠电脑缩小窗口判断兼容性。具体横竖屏交互仍是实施建议，不是已由用户确认的细节。

性能处理沿用现有优化思路：静态背景缓存、动画按需刷新、限制雾层和特效的绘制分辨率、资源先加载再入场；网络只传递必要状态和新增事件，重连时再同步检查点。手机按实测调整画面分辨率与特效强度，不承诺未经真机测量的帧率。

开发阶段可先在本机运行网页和后端，必要时配置局域网手机访问；不需要用户提供服务器密码。公网部署前再确定面向玩家的地区、域名或平台地址、可运行常驻后端的部署环境、预计同时在线人数及受限部署权限。账号系统、观战、原生端互通和地图编辑器是否进入首版，需要在实现主联机闭环后明确，不自动扩张为本次交付范围。
